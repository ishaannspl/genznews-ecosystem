# GenZNews Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Next.js website in `genznews/web/` that shows the published articles the framework stage writes to Supabase, with the design in the design-direction document, runnable locally today from fixtures built out of the pipeline's real output.

**Architecture:** App Router, server components, ISR (300 s). Pages talk only to an `ArticleRepository` interface with two implementations: `FixtureRepository` (JSON built from `output/**/*.md`) and `SupabaseRepository` (reads `site_articles`, published rows only, anon key, server side). An environment switch picks one. Components are small and presentational; the three-line read is the signature component.

**Tech Stack:** Next.js (latest stable, App Router), React 19, TypeScript strict, Tailwind CSS v4 (tokens in CSS), `@supabase/supabase-js`, `react-markdown` + `rehype-sanitize`, Vitest + Testing Library, Playwright + `@axe-core/playwright`. No UI kit, no animation library.

**Spec:** `docs/superpowers/specs/2026-10-05-genznews-framework-site-design.md` section 6, and `docs/superpowers/specs/2026-10-05-genznews-web-design-direction.md` (tokens, layout, copy, quality floor: authoritative for all visual decisions).

## Global Constraints

- Work only under `genznews/web/` (plus `docs/`). Do not modify `app/`, `framework_stage/`, `run_*.py`, `sources.json`, `supabase_setup.sql` or `web/supabase/migrations/0001_site_tables.sql`.
- Pages and components never import `@supabase/supabase-js`; only `src/lib/repositories/supabaseRepository.ts` does.
- Only `PUBLISHED` articles are ever shown: the Supabase repository adds `.eq("status","PUBLISHED")` to every query (RLS is the second layer); the fixture set contains only published articles.
- Server env only: `DATA_SOURCE` (`fixtures` | `supabase`), `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `NEXT_PUBLIC_SITE_URL`, `REVALIDATE_SECRET`. The service-role key never appears in `web/src`, only in the dev seeding script, read from the environment at run time. No secret has a `NEXT_PUBLIC_` prefix. `DATA_SOURCE` defaults to `fixtures` in development and must be set explicitly in production builds.
- Category slugs (exactly five): `health-wellness`, `education-career`, `entertainment-pop-culture`, `biogas-clean-energy`, `digital-marketing-social-media`; they map to database niche keys with underscores (`health_wellness`, and so on).
- Article body format from the stage: `**TL;DR**\n\n- a\n- b\n- c\n\n<body>\n\n---\n\n*<attribution>*\n`.
- Images: plain `<img>` hotlinks only (`loading="lazy"`, `referrerPolicy="no-referrer"`, reserved aspect-ratio box, fallback on error). No `next/image` remote optimization and no `remotePatterns`.
- Markdown is rendered only through `react-markdown` + `rehype-sanitize`; the only `dangerouslySetInnerHTML` allowed is JSON-LD, escaped by `safeJsonLd`.
- Revalidate time 300 s. `/api/revalidate` requires `REVALIDATE_SECRET` (constant-time compare).
- Quality floor (design direction): works at 375, 768, 1024, 1440 px; no horizontal scroll; visible focus; skip link; `prefers-reduced-motion` respected; 4.5:1 contrast in both themes; touch targets at least 44 px; no layout shift from images.
- Copy: sentence case, active voice, strings exactly as in the design direction's copy rules. No em-dashes anywhere in UI text.
- Tests never use the network. Each commit message ends with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Never commit `.env*` (except `.env.example`), `node_modules`, `.next`, or screenshots.

## Review Focus

- A body with no TL;DR block, or with 2 or 4 bullets, or Windows line endings: the page still renders (no three-line read, full body shown) (Task 2, 4).
- `image_url` null, 404, or blocked: category-colored placeholder, no layout shift (Task 4).
- Unknown article or category slug, and an unpublished slug: real 404, not 500 (Task 5, 7). Search with empty text, 5,000 characters, `'`, `%`, `&`, `|`, `:*` and HTML: never errors, never echoes unescaped (Task 3, 7).
- Supabase unreachable or misconfigured: an error state with advice, no stack trace, and the build/sitemap do not crash (Task 3, 5, 6).
- Markdown containing `<script>`, `onerror=`, `javascript:` links or raw HTML: stripped; external links get `rel="noopener noreferrer"` (Task 4).
- Dark theme and reduced motion: readable, and the lead story's three lines are visible immediately (Task 4, 7).

### Task 6b: Real data only and data-source logging (added at the owner's request)

**Why:** the owner wants only real data on the site, never demo articles, and a server console that shows where content comes from and how each choice was made.

**Rules:**
- `DATA_SOURCE` is required in every environment (no default). `fixtures` is allowed only when set explicitly, and then the console prints a loud DEMO DATA warning. With `supabase`, nothing falls back to fixtures: a failure shows the error state.
- A logging layer wraps the active repository (decorator) and prints one line per data call: operation, filters, number of rows (and total), duration, outcome. At first use it prints a source banner (source, Supabase host name only, table, key type, what the key can see) and runs one non-blocking connection check that reports "connected, N published rows" or the classified failure with a fix hint (host not found, connection refused, timeout, 401/403, table missing, JWT problems).
- Pages log their decisions: why a story is the lead, what fills the Latest rail and each category lane, how related stories were picked, how a search was interpreted, and why rows were skipped (unknown category, missing slug or title).
- Never log keys, tokens, full request URLs with query strings, or article bodies. Logging is on in development, off in production unless `DATA_LOG=1`.
